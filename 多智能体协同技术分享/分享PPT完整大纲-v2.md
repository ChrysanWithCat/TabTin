## 逐页大纲

### P1 封面
- 主标题：从一个人爽，到一群人接住
- 副标题：开源项目 TabTin，以及它背后那道 AI 协作还没跨过去的沟
- 标签：技术分享 · 开源项目观察 / 部门技术交流 · 2026.09

### P2 场景引入
- 标题：你让 AI 做的东西，同事接得住吗？
- 正文：你让 AI 做了一下午竞品调研，同事接手第一句是"这个结论怎么来的？数据源链接呢？"你得翻两百条聊天记录。
- 点题：这不是你不负责，是工具帮你把活干完了，却没帮你把过程留下来。

### P3 生产率悖论
- 标题：这不是体感，是统计数字里的鸿沟
- 对照：受控实验个人编码效率提升 20–55% ≠ 十年 TFP 提升 ~0.5%
- 引索洛悖论：到处看得到计算机时代，唯独生产率统计里看不到。
- 本次只聊其中一道：信息在交接中被压平的那道沟。

### P4 单人链已磨完整
- 标题：单用户这条链，已经被磨得很完整了
- 七层栈（自下而上）：Agent 循环 → 记忆与上下文 → 沙箱与权限 → 协议扩展(MCP) → 状态持久 → 编排子代理
- 留白：多人协作、任务接续、上下文共享、方法复用、执行追溯——这一层基本空白。这就是 TabTin 的切入位置。

### P5 多智能体的起点
- 标题：一个很自然的想法——多来几个 Agent 一起干？
- 这是多智能体协同热起来的起点，但它比"多个 agent 聊天"复杂得多，也有坑。

### P6 两种拓扑
- 标题：先别混：这是两种拓扑，不是版本升级
- 左：子代理 / 星型层级——下属只向主线程汇报，彼此零通信；省 token 但有单点。
- 右：多智能体 / 网状对等——队友直接喊话；token 更贵、调试更复杂。
- 现状：Codex 只做到左；Claude Code 的 Agent Teams 想做右，仍在预览。

### P7 汇报损耗
- 标题：它真正填的，是"汇报"这一步的损耗
- 左：子代理信息被压缩两次——A 读 20 个文件，压缩成"建议方案 B"，细节已扔。
- 右：点对点只损耗一次——发现问题的和需要信息的直接对话。
- 这正是 P2"同事接不住"的 agent 版本。

### P8 两盆冷水
- 冷水一：同样多 token，单 agent 不一定输——多 agent 辩论耗 2–5 倍 token，但买的是"独立视角"，不是算力效率。
- 冷水二：共识崩塌——同质小组辩论对小模型反而更差更贵。
- 结论：没有真正异质性的协同，不如不做。

### P9 TabTin 选的路（原页保留）
- 标题：现在看 TabTin：它选了一条不同的路
- 不急着让 Agent 互相聊天，先把"人接续人的工作"做好。
- 四机制：交接=冻结上下文（不是甩摘要）；人 Agent 操作同一份结果；方法固化为可复用 Agent 角色；执行记录可追溯、判断由人做。

### ★ P10 协作四层闭环（新增）
- 标题：TabTin 的协作是四层闭环
- 四层自顶向下：
  1. 团队协作层：Organization / Project / Team Space / Channel / Message
  2. 任务派发层：Project Task / 负责人 / 接受或拒绝 / 状态流转 / 结果验收
  3. Agent 团队层：父 Agent / 子 Agent / 角色派发 / 后台并行 / 汇总回收
  4. 执行治理层：Workspace / Device / HITL 审批 / 预算 / 权限 / 记录
- 一句话：人负责目标、分工和验收；Agent 负责执行、整理和推进；系统负责上下文、权限、状态和证据链。
- 版式：四层纵向堆叠结构图。

### ★ P11 一条任务怎么流完（新增）
- 标题：一条任务：从一条消息到交付物验收
- 流程：
  1. 团队在频道 #general 讨论，材料贴在消息线程里；
  2. 一条消息直接转成 Agent 任务——源消息和回复线程自动带入，不用复制粘贴；
  3. 创建 Project Task 指定负责人，负责人接受 / 拒绝；
  4. 负责人选自己的 Agent + Workspace + Device；
  5. prepare run → start run，Agent 在负责人执行现场推进；
  6. 过程产生 comments / events / 交付物；
  7. 团队验收 accept result，沉淀 deliverables。
- 点题：这不是普通 ToDo——它带会话、带交付物、带验收状态，是 AI 原生任务。
- 版式：横向流程图。

### P12 不是套壳（原页保留）
- 标题：不是套壳：全栈开源，架构也较真
- 开源范围：Electron 桌面端 + 移动端 + 服务端 + Agent Runtime + 实时协作 + 管理后台，AGPL-3.0，可自部署。
- 三个架构决策：Agent ≠ Device（身份与执行环境解耦）；交接 ≠ 共享整个目录；开源真实产品代码。

### ★ P13 Agent 组队（新增）
- 标题：Agent 也组队：受控派发，不是网状聊天
- role（谁来做）和 prompt（做什么）分离——子 Agent 是可被识别的工作成员，不是匿名工具调用。
- 后台并行 fan-out，wait_agent_ids 汇总 fan-in。
- 默认不继承父对话上下文（最小必要）——子 Agent 只看自己那份自包含任务，避免被父会话原文污染。这正好呼应"信息别被压平"。
- readonly 审查员 vs 执行员分开；有队列、预算、嵌套深度保护。
- 落点：受控的 star / mission 模式，不是无限自治的网状 agent 社会。
- 版式：父 Agent 派 3 个子 Agent 的示意图。

### ★ P14 交接四档（新增）
- 标题：交接的四种档位：看、说、抄、接
- 实时查看：跟进进展，不能操作发送方现场。
- 实时协作：可以在任务里发言驱动 Agent；执行、审批、费用仍在任务所有者这边。
- Fork 抄走：可实时查看，并复制成自己的任务继续推进。
- 交给同事继续：冻结上下文、带上引用材料，接收人选自己的 Agent 和 Workspace，创建独立续接任务。
- 点题：看、说、复制、接手是四种不同权限；交接不等于把你的电脑目录开放给别人。
- 版式：四张并列卡片。

### P15 对比表（原页保留）
- TabTin vs Codex vs Claude Code：设计假设、沙箱、检查点、协作模型、工作交接、定位。
- 落点：Codex/CC 优化单人执行闭环；TabTin 补团队协作层，不是全赢。

### ★ P16 技术纵深（新增·弹性页）
- 标题：它背后怎么撑起来
- 后端六件套一句话：Django 管业务 / PostgreSQL 存事实 / Redis 做高速中间层 / Celery 跑后台任务 / Centrifugo 推实时消息 / OSS 存大文件。
- 两个实时通道：Centrifugo = 聊天/通知型广播；自研 WebSocket Gateway = Agent 流 + 设备控制 + HITL 审批 + 弱网恢复。
- 三档审批：always_ask / auto / full_access；群协作空间强制 always_ask。
- 沙箱：应用层 judge + 可选 OS 级沙箱（Linux bwrap / macOS sandbox-exec / Windows 降级）。
- 定位：后端、测试同事感兴趣；时间紧可跳过，留作 Q&A。
- 版式：架构分层图。

### P17 合流（原页保留）
- 标题：两条路，填的是同一道沟
- 左：多智能体协同——保护 agent 之间的独立视角，不被层级汇报压平。
- 右：TabTin——保护人之间的工作上下文，不被交接丢掉。
- 共同敌人：信息从一个工作主体传到另一个时，在"汇报/交接"这一步被压成有损摘要。

### P18 行动建议（原页保留）
- 标题：不用等平台，今天就能开始一件事
- 下次用 AI 做完东西，别只丢最终文件——把"为什么这么判断、参考了哪些资料、否掉了哪个方案"一起交出去。
- 核心一句：让工作能被下一个人接得住。
